The governing rule

Separate before you combine

A headline, an official notice, a vessel movement and a market return are not interchangeable measurements. Sensor Fusion places event-linked observations into registered semantic lanes, keeps their rights and knowledge times attached, and reports absence against an eight-lane denominator. It performs no cross-lane conversion and emits no observed value.

What the engine refuses

  • An unsigned, invalid or rights-drifted canonical release.
  • A source role registered to zero lanes or more than one lane.
  • An evidence type incompatible with its lane, or more linked evidence than the registered bound.
  • An observation retrieved after the knowledge cutoff, or a query window extending past it.
  • A rewritten lane label, false coverage count, reordered partition or hidden missing lane.
  • Source text, URLs, observed values, event intensity, risk scores, probabilities, causal claims or forecasts in the structural output.

Machine contract

python -m src.sensor_fusion RELEASE.json EVENT_ID \
  --window-start 2026-08-08T08:30:00Z \
  --window-end 2026-08-08T11:00:00Z \
  --knowledge-cutoff 2026-08-08T13:00:00Z

The engine revalidates the signed canonical release, source-rights snapshot, executable method bytes, common schema, output schema and eight-lane registry before returning a hash-bound matrix. A complete matrix means only that every registered lane has at least one eligible event link in that release and window.

What must happen before production

IGRM still needs rights-approved production sources, externally controlled release signing, production canonical events, source-specific acquisition receipts, and independently reviewed lane mappings. It must then publish coverage denominators and known missingness for each lane. Until those gates pass, the page demonstrates an executable architecture—not a live world-state engine.
