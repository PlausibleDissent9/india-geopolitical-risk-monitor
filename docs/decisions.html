Why this is a program and not a list

A hand-written to-do list is a claim with nothing checking it. It goes stale the moment an item is finished somewhere else — in a chat, on a phone, at two in the morning — and then it keeps asserting itself in exactly the same confident tone as the parts that are still true. This project has spent a lot of effort deleting artifacts of that shape.

So every item here carries a predicate: a function that reads the repository and answers whether the thing is still undone. The DOI item is open because CITATION.cff has no doi: field. Calibration is open because precision.json reports its own label count against its own registered threshold. Nobody marks these complete; they stop being true. An item that cannot be checked this way does not belong on the page.

The distinction that decides what lands here: these are not tasks that need doing, they are decisions that need authority. Minting an identifier, signing a registration, labelling a validation set, choosing what the paper argues. Automating any of them would not be efficiency, it would be forgery — a machine that labels its own precision set has built a mirror, not a check.
