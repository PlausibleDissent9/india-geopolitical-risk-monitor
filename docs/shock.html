The governing rule

Compile assumptions. Never predict around missing evidence.

The engine traverses only stored-direction paths in a signed canonical release. It carries every original denominator, source-age policy and hypothetical assumption into the result. One-hop, interval-valued, unit-compatible paths can be transformed; every unsupported path remains visible and abstains.

      The refusal boundary

      • A point-only magnitude or duration presented where a bounded interval is required.
      • An unsigned, rights-drifted, schema-invalid or temporally inconsistent release.
      • A scenario whose knowledge cutoff differs from its signed release timestamp.
      • Multiplying across multiple hops or unlike units without a registered transform.
      • Hiding a stale edge, unused assumption, truncated search or missing path.
      • Any output flag that implies forecasting, probability, causation, advice or a scalar score.

      Machine contract

      python -m src.shock_compiler RELEASE.json SCENARIO.json --output compilation.json
python -m src.shock_compiler_fixture

      The engine validates the release, scenario, policy registry, schemas, implementation, exposure traversal and source-rights bytes before compilation. Revalidation recompiles the complete output from those signed inputs and requires exact semantic equality.

      What must happen before production

      IGRM still needs rights-approved real exposure releases, declared India entity universes, independently audited edge intervals, registered multi-hop transforms where defensible, user-specific scenario isolation and deletion, external signing control, and blinded decision-utility tests. Until then this page proves executable architecture and refusal behavior—not real-world coverage, model accuracy, institutional readiness or adoption.
