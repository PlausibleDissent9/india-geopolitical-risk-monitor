# IGRM Continuous Evolution Engine 1.0

Status: observer implementation; automatic code change and publication are not
authorized.

## Why this engine exists

IGRM Max cannot be a frozen feature list. A fixed launch denominator is useful
because it prevents quiet scope loss, but it becomes harmful if it is mistaken
for the permanent ceiling. The Continuous Evolution Engine separates those two
ideas:

- the October contract is the minimum that must not silently shrink; and
- the improvement queue may expand whenever evidence exposes a better problem,
  source, method, interaction, product or standard.

The engine is not an autonomous maintainer. A public research instrument that
rewrites itself to look busy would optimize motion, not truth. Version 1 is a
read-only observer and deterministic public ledger. It makes the improvement
loop measurable before any class of automatic release is considered.

## The loop

```text
observe a measured gap
  -> specify the user, denominator and success condition
  -> classify the change risk
  -> implement in a bounded surface
  -> generate and run adversarial evidence
  -> satisfy the registered authority
  -> bind one exact green commit
  -> release atomically with rollback evidence
  -> measure the user, coverage and operational result
  -> accept, amend or roll back
```

An idea does not become an improvement because code exists. It becomes an
improvement only after the post-release measurement supports the stated success
condition. Failed experiments and rollbacks remain in the ledger.

## Hourly does not mean reckless

The scheduled scout may:

- read committed public registries and payloads;
- measure registered denominators and gaps;
- run integrity and staleness probes;
- produce a short-lived audit artifact; and
- rank already registered improvement candidates.

It may not:

- modify the repository or public site;
- add a source or approve a rights use;
- change a score, construct, weight, method or benchmark;
- author a public fact or comparative claim;
- handle a private signing key or restricted source; or
- record a citation, award, study result or adoption event without authentic
  external evidence.

Low-risk automated promotion is a future study, not a hidden feature. It requires
a measured observer history, exact-green-commit publication, independent attack,
rollback drills and a founder-approved authority statement that names the exact
eligible change class.

## Quality surface

Every candidate must target at least one of eight dimensions: truth, coverage,
utility, experience, reliability, security/privacy, reproducibility/citation or
institutional adoption. Each dimension has its own evidence. Page count, source
count, test count and model count are never universal progress measures.

The first measured gaps are deliberately uncomfortable:

- the world map has 247 country/area geometries, but the current India-partner
  event layer observes 193 and exposes no visible global-layer denominator;
- fifteen global layer families are registered, but only one country-level layer
  currently carries public observations;
- the 1979–2019 proxy publishes only two defensible channels and is used mainly
  as an archival research page rather than an operating historical intelligence
  layer; and
- every protected route exists, but route existence is not evidence that every
  route has passed the same independent decision-task and assistive-technology
  evaluation.

These are improvement inputs, not product claims.

## Historical Intelligence program

The 1979 record is activated through separately registered uses:

1. regime-conditional baselines and percentiles;
2. structural-break and source-boundary diagnostics;
3. event archetypes with explicit selection rules;
4. analog retrieval that reports disanalogies as prominently as similarities;
5. rival-hypothesis comparison; and
6. point-in-time replay of what an earlier release or source vintage could have
   supported.

The monthly historical proxy remains a different construct from the daily live
index. Evolution creates new tools around that evidence; it does not splice the
series, manufacture missing channels or use later knowledge in earlier states.

## Global Consequence program

`governance/global_atlas_layers.json` registers fifteen independent layer
families. It prohibits one universal world score and requires every mapped
country/area geometry to appear as observed, unavailable, withheld,
not-applicable or out-of-scope in every country-level layer. Defence resources,
weapon inventories, arms transfers and military activity are deliberately
separate because spending, ownership, delivery, readiness, posture and live
movement are different constructs with different safety boundaries.

The first visible World State Matrix will therefore look incomplete on purpose.
Its job is to make the missing world measurable, then replace unavailable cells
with rights-cleared observations one source and construct at a time.

The next program is the Global Event and Episode Ledger described in
`design/category_architecture.md`. The ledger must distinguish source
observations, unique events and multi-event episodes; freeze a complete census
denominator; preserve hierarchy and lifecycle revisions; and compute the
correction blast radius across every dependent product. A world marker count is
not an episode census.

## Machine surfaces

- `governance/evolution_engine.json` — authority, cadence, risk and strategic
  program contract.
- `governance/global_atlas_layers.json` — global layer denominator and claim
  boundaries.
- `design/category_architecture.md` — eight-plane category architecture and
  compounding capability backlog.
- `design/claude_adversarial_review_protocol.md` — independent attack and verdict
  contract for every shipped slice.
- `src/evolution_engine.py` — offline deterministic observer.
- `docs/data/evolution.json` — public measured state and priority queue.
- `.github/workflows/evolution.yml` — read-only hourly scout; never a publisher.
