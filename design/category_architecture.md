# IGRM Max category architecture

Status: governing target architecture; a capability is not public merely because
it appears in this document.

Effective: 2026-08-09

## Category

IGRM Max is an **open, proof-carrying geopolitical consequence system for
India**. It is designed to preserve what was knowable, distinguish observation
from inference, trace how an external event could reach India, test bounded
responses and measure what later happened. The current press-salience instrument
is one sensor inside that system. It is not the whole system and it is not a
universal risk score.

The product is successful only when one governed state can compile all of the
following without changing the underlying facts:

- a citable research object and exact subset manifest;
- a business exposure path and bounded scenario;
- a journalist claim card with contradicting evidence;
- an institutional audit bundle that works offline; and
- an evidence-locked assistant answer that abstains when the plan is unsupported.

## Two inseparable chains

Every consequence product must preserve this analytical chain:

```text
Observation
  -> Claim
  -> Canonical event
  -> Episode
  -> Mechanism
  -> Exposure
  -> Constraint
  -> Feasible option
  -> Outcome
  -> Calibration or recorded loss
```

Every link must also preserve this trust chain:

```text
Source frame
  -> Rights decision
  -> Coverage denominator
  -> Independence and syndication state
  -> Freshness and knowledge cutoff
  -> Typed missingness
  -> Typed uncertainty
  -> Correction impact
```

A chain is not complete when a field is non-null. It is complete only when its
input frame reconciles, its source use is authorized, its transformation is
registered, its dates cannot leak later knowledge, its uncertainty is typed and
its correction path is executable. A broken link produces a refusal or a visible
limitation, never fluent replacement prose.

## Eight planes

### 1. Evidence Mesh

An append-oriented, rights-aware evidence layer stores or references exact source
records, translations, hashes, retrievals, corrections, source relationships and
the run that consumed each record. A source-dependency graph marks common
ownership, syndication, mirrors and shared upstream reporting so five copies of
one report cannot become five independent confirmations.

### 2. Observation Twin

The Observation Twin records what each registered source could support at every
knowledge cutoff. It is deliberately distinct from the best current
reconstruction of reality. It makes vintage changes, outages, publication delays,
revisions and source disagreement queryable without hindsight leakage.

### 3. Global Event and Episode Ledger

The ledger turns geopolitical activity into typed, versioned objects rather than
headlines. It separates rumour, allegation, official position, confirmed action,
realized disruption, response and recovery. It represents event hierarchy,
mergers, splits, escalation, dormancy, recurrence and resolution.

The first public ledger must publish a census contract before it publishes a
world count:

- declared source frame and geographic/time denominator;
- event and episode definitions and stable identifiers;
- inclusion, exclusion, duplicate and hierarchy rules;
- provisional, disputed, confirmed, closed and superseded states;
- unique events, active episodes and event observations as different counts;
- per-country coverage and missingness, including zero-source areas;
- disagreement, independence and revision histories; and
- a reproducible snapshot and point-in-time replay.

No press aggregate, map marker or model candidate may be described as a global
event census until this contract passes.

### 4. World State Matrix

Every registered country or area appears in every registered country-level
domain as observed, unavailable, withheld, not applicable or outside a declared
scope. The matrix prohibits a universal world score and cross-domain averaging.
Its empty cells are a measured build queue. Each populated cell must resolve to
the same event, episode, source, rights and vintage objects used elsewhere.

### 5. India Consequence Twin

The twin maps typed external events through versioned Indian dependencies:
countries, treaties, commodities, technologies, corridors, ports, critical
assets, firms, sectors, states, ministries, buffers, capacities, substitutes and
activation lags. Each universe is declared before its coverage is reported.

The primary advantage is not a bigger graph. It is a graph whose covered and
unmapped members reconcile to a real source frame, whose edges carry effective
dates and whose topology can be independently sampled. One exceptional vertical
must be completed before breadth is used as a claim.

### 6. Mechanism and Decision Lab

The lab keeps four questions separate:

1. what followed an event;
2. which mechanism is compatible with the evidence;
3. what can be attributed under a registered causal design; and
4. which response remains feasible under uncertainty.

Mechanisms declare required observations, rival hypotheses and falsifiers.
Scenarios propagate intervals, not point certainty. Constraint solvers enforce
stocks, flows, capacities, substitution ceilings, activation lags, geographic
routes and policy applicability. Decision outputs optimize robustness or minimax
regret only for registered objectives; they are never disguised forecasts.

### 7. Proof-Carrying Product Compiler

Natural-language and interface requests compile into finite allowlisted plans.
Every sentence, number, map mark and scenario path carries a claim and evidence
bundle hash. The compiler produces researcher, board, newsroom, public, API and
offline-audit views from the same governed objects. It refuses orphan claims,
unsupported arithmetic, invalid temporal joins, incompatible rights,
unregistered methods and stale evidence.

### 8. Evolution and Institution

IGRM keeps a permanent register of benchmark losses, false alerts, missed events,
abstentions, incidents, corrections, user failures and retired assumptions. The
hourly observer may measure registered gaps and propose bounded work. It may not
change evidence, methods, rights, claims, security boundaries or releases.

External adoption, citations, awards and government use are recorded only from
authentic outside evidence. Reliability, security, privacy, succession, funding,
support and correction capacity are product capabilities, not administrative
afterthoughts.

## Compounding capability backlog

The following capabilities are additive. None replaces an earlier promise:

1. cross-provider event resolution with stable identifiers;
2. a global episode census with explicit event/episode/observation counts;
3. event hierarchy and morphology: parent, child, merge, split and recurrence;
4. event lifecycle and typed confirmation transitions;
5. point-in-time Observation Twin replay;
6. source ownership, mirror and syndication dependency graph;
7. bounded shadow-denominator diagnostics for unseen or inaccessible events;
8. evidence authenticity and acquisition-chain verification;
9. narrative lineage showing how claims spread and changed;
10. entity and crosswalk foundry with effective dates and unresolved identities;
11. correction blast-radius computation across every dependent product;
12. release-calendar and revision-surprise evidence for economic transmission;
13. registered mechanism library with rival hypotheses and falsifiers;
14. interval and missingness propagation through consequence paths;
15. dependency cut-set and single-point-of-failure analysis;
16. an identifiability certificate for every causal claim;
17. minimax-regret and robust-option comparison;
18. sensitivity frontiers rather than one scenario output;
19. disanalogy-first historical retrieval;
20. policy-jurisdiction and applicability compiler;
21. geospatial precision and safety compiler for sensitive activity;
22. rights-aware query planning and selective disclosure;
23. private organizational clean rooms with public method verification;
24. a prospective alert-loss ledger; and
25. claim subscriptions with signed correction and state-change notices.

## Ten-week engineering order

The ten-week target is an auditable release candidate, not manufactured adoption:

1. **Weeks 1–2:** World State Matrix, evolution ledger, category contracts,
   claim compiler boundary and public missingness denominator.
2. **Weeks 2–4:** Global Event and Episode Ledger, candidate reconciliation,
   episode census contract, point-in-time state transitions and correction graph.
3. **Weeks 3–6:** one rights-cleared India consequence vertical with a declared
   universe, audited edges and complete missingness.
4. **Weeks 5–7:** mechanism library, bounded scenario propagation, feasibility
   checks, rival-hypothesis display and correction blast radius.
5. **Weeks 6–8:** historical regimes, structural breaks, disanalogy-first analogs
   and knowledge-cutoff replay using only defensibly comparable series.
6. **Weeks 7–9:** typed research, board, newsroom, API and audit-bundle compiler;
   assistant plans may expand only after the underlying objects pass.
7. **Weeks 9–10:** total-site institutional redesign, accessibility and
   low-bandwidth evaluation, threat exercises, restore drills, independent review
   packets and a rights-safe authenticated release candidate.

Parallel work may shorten engineering time. It cannot compress independent
coding, prospective observation, legal authorization, citation history,
institutional use or longitudinal reliability into a claim that already exists.

## Benchmark strategy

IGRM does not try to beat unlike instruments on one invented score. It absorbs
their strongest properties and competes on declared tasks:

- GPR, EPU and WUI: construct discipline and historical comparability;
- ACLED and UCDP: event ontology, coding and revision practice;
- BDI and physical-flow sources: narrow real-economy measurement;
- CPI, ICRG, INFORM and governance/risk systems: institutional structure,
  exposure and decision relevance;
- WorldMonitor and WarWatch: fast visual situational awareness.

IGRM's intended category advantage is the combination those products do not
jointly provide: point-in-time evidence, typed event episodes, an India
consequence graph, constraint-aware scenarios, proof-identical outputs,
rights-aware reproduction and a public loss/correction record. Each part still
requires its own registered proof.

## Definition of Max

“Max” is not a fixed feature list and not an hourly demand for visible novelty.
It is the invariant that every measured failure becomes a candidate for a safer,
more useful and more complete system without weakening an already earned
capability. The roadmap can expand continuously. Public truth, rights, security,
accessibility, denominators and correction duties may not be traded away for
speed or spectacle.
